# Chase's Google Form Limiter平台

多組織版本：**你只提供平台（這個網站）**，替每個組織開帳號。每個組織自己連接 **自己的 Google 帳號**、設定**自己的資料夾**和**自己的寄信帳號（Google Apps Script）**，平台就會控管他們資料夾裡的表單。

- **跟你的 Google 帳號無關**：平台不複製、不建立任何檔案。表單、回覆、上傳的檔案、寄信額度都是組織自己的
- 名額上限、開放時間、截止時間：每分鐘自動檢查，到了就開關表單
- **依送出順序排位**：超出名額的人自動收到「候補」信；之後有人被刪除、候補排進名額內，再寄「遞補成功」信
- 畫面上方的組織選單：**全組織**（所有組織、平台設定）、組織一、組織二…；右上角是登入的帳號（改密碼、登出）
- 選了組織之後有「首頁、帳號、組織設定、管理表單、數據」分頁；「管理表單」和「數據」都先用下拉選單選一份表單；測試、寄信紀錄都是整頁，不是跳窗；所有修改都用右下角的「儲存」／「重置」一次處理
- 每個組織只看得到自己的資料，操作紀錄只有平台擁有者看得到
- 部署新版時有 **30 秒緩衝**，舊版會把正在做的檢查和寄信做完、把資料寫回磁碟才關閉
- 零套件依賴：Node.js 22.13 以上，資料庫用 Node 內建的 SQLite

```
server.js            進入點
lib/app.js           API 與權限
lib/google.js        Google OAuth、Drive、Forms API
lib/limiter.js       規則判斷、排位、寄通知、模擬測試、每分鐘排程
lib/quota.js         選項名額：讀段落與選擇題、移除／加回選項、找出超額回覆
lib/mailer.js        寄信（組織自己的 GAS）
lib/gas-relay.js     組織 GAS 寄信中繼站的程式碼範本
lib/db.js            SQLite 資料表
lib/security.js      密碼雜湊、加密
lib/runtime.js       自動偵測 Volume、產生金鑰、各組織的 Google 用戶端與寄信設定
public/index.html    網頁介面
railway.json         Railway 設定（啟動指令、健康檢查、30 秒緩衝）

```

## 一、Railway 部署（只要點兩個地方）

1. Railway → New Project → **Deploy from GitHub repo** → 選 `chase5ws/2026_google_form_limiter`。Railway 會用最外層的 `Dockerfile`（官方 `node:22-alpine` 映像檔）建置，並讀取 `railway.json`，什麼都不用設定。
2. **Settings → Networking → Generate Domain**，拿到 `xxxx.up.railway.app`。
3. **掛 Volume**：在服務上按右鍵 → **Attach Volume**，掛載路徑填 `/data`。

就這樣，**不用設定任何環境變數**：

| 原本要手動設的 | 現在 |
|---|---|
| `DATA_DIR` | 自動讀取 Railway 提供的 Volume 掛載路徑 |
| `ENCRYPTION_KEY` | 第一次啟動自動產生，存在 Volume 裡的 `.encryption-key` |
| `APP_URL` | 自動讀取 Railway 網域 |
| Google 用戶端、Google 帳號、寄信 | 各組織在網頁「組織設定」自己填，你不用設定 |

> 想用指令完成第 2、3 步也可以（要先 `npx @railway/cli login` 並在 repo 資料夾執行 `npx @railway/cli link`）：
> ```bash
> npx @railway/cli volume add --mount-path /data
> npx @railway/cli domain
> ```

## 二、打開網站

1. 打開網域登入：有設 `ADMIN_ACCOUNT`／`ADMIN_PASSWORD` 就用那組帳密直接登入；沒設的話用 **`chase5ws` / `chase5ws`**，第一次會要求改密碼。
2. 組織選單選 **全組織 → 平台設定**：確認網域和 Volume 都顯示「完成」。**平台設定只有 `ADMIN_ACCOUNT` 這個帳號（平台擁有者）看得到**，其他平台管理員只能管理組織。
3. **全組織 → 所有組織 → 建立組織**，把帳密私訊給組織管理員。其他的 Google、資料夾、寄信設定都由組織自己做。

> 從舊版升級：以前平台共用的 Google 用戶端和帳號，如果只有一個組織，會自動搬給那個組織，不用重新設定；有多個組織的話會清掉，請各組織自己到「組織設定」連接。

### 進階：用環境變數覆蓋（選填）
有設定的話會優先使用，網頁上就不能改。

| 變數 | 用途 |
|---|---|
| `ENCRYPTION_KEY` | 自訂加密金鑰（設定後不要改，改了各組織要重新設定 Google 和寄信） |
| `DATA_DIR` | 自訂資料位置 |
| `APP_URL` | 綁自訂網域時填，例如 `https://forms.example.com` |
| `CHECK_INTERVAL_SECONDS` | 檢查間隔，預設 `60` |
| `ADMIN_ACCOUNT` | 平台管理員帳號，預設 `chase5ws`（3–32 個英文小寫、數字、. _ -） |
| `ADMIN_PASSWORD` | 平台管理員密碼，第一次登入不用改；忘記密碼時換一個值，見下方說明 |

**之後每次 push 到 `main`，只要改到平台的程式（`server.js`、`lib/`、`public/`、`package.json`、`railway.json`），Railway 就會自動重新部署。** 只改文件不會觸發。資料存在 Volume，不受部署影響。

### 部署緩衝（30 秒）
`railway.json` 已設定 `drainingSeconds: 30`：部署新版時，舊版先收到 SIGTERM，30 秒後才會被強制關閉。這段時間舊版會：
1. 不再接受新的請求（回應「系統正在更新，請 30 秒後再試」）
2. 等目前的表單檢查、寄信做完
3. 把 SQLite 的 WAL 寫回主檔，再關閉

如果 Railway 後台的 Settings → Deploy 有另外設定 Draining Seconds，以後台為準，記得也設成 30。

### 平台管理員帳密（建議設定）
在 Railway → 服務 → **Variables** 新增兩個變數：

| 變數 | 值 |
|---|---|
| `ADMIN_ACCOUNT` | 你的帳號，例如 `chase5ws`（沒設就是 `chase5ws`） |
| `ADMIN_PASSWORD` | 你的密碼 |

- 直接用這組帳密登入，**第一次不用改密碼**。
- 之後改 `ADMIN_ACCOUNT` 會**另外建立**一個新的平台管理員，舊帳號不會被刪除，可以在「全組織 → 平台設定 → 平台管理員」停用或刪除。新的帳號會成為平台擁有者，只有它能使用平台設定。
- 之後一樣可以在網頁右上角「改密碼」自己改。重啟或重新部署**不會**把它改回去，因為同一個值只會套用一次。
- **忘記密碼時**：把 `ADMIN_PASSWORD` 改成另一個值，重新部署後就能用新的值登入。所有裝置會被登出，登入鎖定也會解除。
- 密碼只存在 Railway，**不要寫進程式碼**，因為這個 repo 是公開的。

沒設 `ADMIN_PASSWORD` 的話，預設帳密是 `ADMIN_ACCOUNT`（或 `chase5ws`）／`chase5ws`，第一次登入會要求改密碼。

組織的帳號忘記密碼：由組織管理員或平台管理員在「帳號」分頁按「重設密碼」。

## 三、日常使用

### 平台管理員（你）
1. **全組織 → 所有組織 → 建立組織**：填組織名稱和第一位組織管理員。帳密會自動複製到剪貼簿，私訊給對方。
2. 表格裡可以看到每個組織的 Google 帳號、資料夾、寄信有沒有設定好；按「進入」（或從上方組織選單選）可以替他們處理。
3. **替組織新增管理員**：該組織的「新增管理員」，預設權限就是組織管理員。

### 組織管理員
1. 用拿到的帳密登入，改成自己的密碼。
2. 到 **組織設定 → 1. Google 帳號**，用你們自己的 Google 帳號：
   1. 到 Google Cloud 建立專案，啟用 Forms API 和 Drive API。
   2. OAuth 同意畫面：學校或公司的 Google Workspace 帳號選「**內部**」（不用審核、不會有未驗證警告）；一般 Gmail 選「外部」，**按「發布應用程式」**，不然授權每 7 天就會失效。
   3. 建立用戶端，類型選「網頁應用程式」，「已授權的重新導向 URI」按頁面上的「複製」貼上。把用戶端 ID 和密鑰貼回平台，儲存。
   4. 按「連接 Google」，用同一個帳號登入並允許。
3. **組織設定 → 2. 資料夾**：在這個 Google 帳號的雲端硬碟建立資料夾（名稱隨意），把表單放進去，貼上資料夾連結。
4. **組織設定 → 3. 寄信帳號**（要寄候補／遞補通知才需要），用 Google Apps Script 從你們的帳號寄信，**不用設定 DNS**：
   1. 按「產生程式碼」→「複製」。
   2. 用要寄信的帳號打開 [script.google.com/create](https://script.google.com/create)，貼上程式碼並儲存。
   3. 部署 → 新增部署作業 → 網頁應用程式。執行身分選「我」，誰可以存取選「所有人」，然後部署並授權。
   4. 把「網頁應用程式網址」貼回平台，儲存。平台會自動測試連線，並抓出寄件帳號。再寄一封測試信確認。
   - 額度：Google Workspace 帳號每天約 1,500 封，一般 Gmail 約 100 封。程式碼裡有專屬密鑰，沒有密鑰的人沒辦法透過這個網址寄信。
5. **首頁 → 資料夾裡的表單**：按「加入管理」，接著設定名額、開放和截止時間、選項名額。需要的話，勾選「名額已滿時寄信通知」。
6. 之後在 **數據** 用下拉選單選表單，看狀態、名額（例如「3（max:15）」）、即時動態、開關、測試；在 **管理表單** 用下拉選單選表單來設定。
7. 填寫連結**不變**，照常發給大家就好。
8. 「帳號」分頁可以新增同事。組織成員能管理表單，但不能改組織設定和帳號。

### 選項與名額（例如場次 A 30 人、B 20 人）
1. **管理表單** → 下拉選單選表單 →「段落：選項、名額與寄信通知」：平台會讀出表單的**段落**和裡面的單選、多選、下拉題，預設顯示最後一段；段落下拉選單的第一項是「名額已滿時寄信通知」。
2. 選第幾段，每一題都可以直接修改，改完按右下角的「儲存」（改錯了按「重置」），名額與時間、各題、寄信通知會一次存好：
   - 題目名稱、選項名稱，新增、刪除選項，按住左邊的 ⠿ 拖拽調整順序（也可用鍵盤上下鍵），會直接寫回 Google 表單（「其他」選項和跳到某段落的設定會保留）。
   - 每個選項的名額，留白代表不限。
   - 改名後，之前選舊名稱的回覆仍會算在這個選項上。
3. 每分鐘檢查一次：
   - 某個選項額滿 → **從表單移除這個選項**，填寫者就選不到了。
   - 有人被刪除、或名額調高 → **依原本的順序把選項加回去**。
   - 一題裡有設名額的選項全部額滿 → 不會把選項刪光，改成**關閉整份表單**（狀態顯示「選項皆已額滿」）。
   - 「其他」選項不受名額限制。
4. 系統移除選項之前就搶先送出的人，會收到候補信，信裡用「額滿的選項」／「額滿說明」寫明是哪個選項額滿。
5. 把一題的名額全部留白並儲存，被移除的選項會全部加回。

### 數據
「數據」分頁用下拉選單選一份表單：狀態、名額、選項電池，以及即時動態：
- 總回覆、今天、最近 1 小時、剩餘名額，以及最近 24 小時每小時的送出數。
- 最新 100 筆回覆，最新的在最上面，標出正取／候補（候補會寫明是哪個選項額滿），新進來的會標底色。每 20 秒自動更新，資料直接從 Google 表單讀取。
- **回覆試算表**：在 Google 表單「回覆 → 連結至試算表」，再到試算表「檔案 → 共用 → 發布到網路」，把連結貼上，按右下角的「儲存」，這一頁就會顯示試算表。注意發布後知道連結的人都看得到，而且 Google 大約每 5 分鐘才更新一次。

### 測試按鈕
「數據」頁的「測試」（整頁）：選一個選項、填模擬幾筆和你的 Email，按「模擬送出」。
- 會列出模擬前後表單狀態、每個選項的名額變化，以及會收到候補信的人數和信件內容。
- 如果模擬的報名超額，會把那封候補信加上「[測試]」寄給你，順便確認組織的寄信帳號能用。
- **不會改動真的表單、回覆和寄信紀錄。**

### 名額已滿通知怎麼運作
- 每分鐘讀一次回覆，依**送出時間**排位。第 1 到 N 名是正取，N+1 名之後是候補。
- 候補的人會收到「候補」信，例如「您的報名順位是第 32 位（候補第 2 位）」。
- 管理員在 Google 表單刪掉某筆回覆後，排位會重算。原本候補、現在排進名額內的人，會收到「遞補成功」信。
- 每人每種信只寄一次。寄失敗會重試，最多 3 次。卡片上的「寄信紀錄」可以看到每一封信的狀態。
- 收件 Email 有兩種來源：
  - 表單開啟「收集電子郵件地址」（表單設定 → 回覆）
  - 另外指定一題讓填寫者輸入 Email 的簡答題
- 信件主旨和內容可以直接修改。點主旨和內容中間的「表單名稱、組織、順位、名額、候補第幾位、額滿的選項、額滿說明」按鈕，會插入到游標位置，寄出時換成實際內容。按「恢復預設內容」可以還原。

## 誰的帳號做什麼

| 用途 | 帳號 |
|---|---|
| 提供網站、建立組織 | **你**（平台擁有者），只需要 Railway |
| Google OAuth 用戶端、開關表單、讀回覆 | **組織**自己的 Google Cloud 專案和 Google 帳號 |
| 資料夾、表單、回覆、上傳的檔案 | **組織**自己的雲端硬碟，容量也算組織的 |
| 寄候補／遞補通知 | **組織**自己的 Google Apps Script（組織設定 → 寄信帳號）；沒設定就不寄 |

## 雲端硬碟與權限

- 平台**不會**建立或複製任何檔案。
- 組織授權給平台的 Google 權限只有三項：
  - 讀取雲端硬碟的**檔案清單**（`drive.metadata.readonly`），用來列出資料夾裡的表單
  - **開關表單、調整選項**（`forms.body`）
  - **讀取回覆**（`forms.responses.readonly`），用來計算份數和排位
- 只能加入**放在組織設定的資料夾裡**的表單，其他地方的表單會被拒絕。
- 組織中斷 Google 連接或撤銷授權後，該組織的表單會停止自動檢查，停在最後的狀態。

## 安全設計

- 密碼用 scrypt 雜湊。各組織的 Google 授權、用戶端密鑰、GAS 密鑰都用 AES-256-GCM 加密後存放，金鑰存在 Volume 的 `.encryption-key`（權限 600）或環境變數 `ENCRYPTION_KEY`。
- Session 存在 HttpOnly Cookie，12 小時沒有動作就失效。改密碼、被停用或被重設密碼時，舊的登入會立即失效。
- 寫入類 API 都要帶自訂標頭，用來防 CSRF。同一帳號連續登入失敗 5 次，會鎖 15 分鐘。
- 組織之間完全隔離：每個 API 都會檢查目前使用者屬於哪個組織。

## 限制

- 每分鐘檢查一次，人很多時可能會多收幾份。Google 表單本身沒有硬上限。
- 每個組織用自己的 Google 專案呼叫 API，配額各自計算。單一組織同時管理的表單大約到 100–150 份時會碰到 Forms API 的每分鐘配額，這時把 `CHECK_INTERVAL_SECONDS` 調高，例如 `120`。
- 每次檢查最多寄 30 封信，其餘的下一分鐘繼續寄。
- Forms API 不能改「表單已關閉」時的提示文字，會顯示 Google 預設的訊息。
- 2025 年以前建立的**舊版表單**不能用 API 開關。請在 Google 表單按「⋮ → 建立副本」，副本是新版格式。
- SQLite 只能跑 1 個實例。`railway.json` 已經設好 `numReplicas: 1`。
